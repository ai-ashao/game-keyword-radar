## 1. 产品目标

开发一个运行在 Mac 本地的游戏关键词研究 Dashboard。用户可以点击扫描 Steam 游戏，看到候选游戏、规则化关键词集群、证据完整度和下一步验证建议。

V1 回答的是：

> 今天有哪些游戏工具、攻略或数据库主题值得继续查 SERP？

V1 不回答：

- 一个关键词有多少月搜索量；
- 某个页面一定能获得多少流量；
- 某个机会一定值得立即开发。

## 2. 交付形态

```text
浏览器 http://127.0.0.1:3000
                |
                v
       FastAPI 本地 Dashboard
          |        |        |
          v        v        v
     Steam采集  规则分析  JSON/Markdown
          |
          v
   可选 Google Trends

Codex Skill -> 调用 CLI / 阅读快照 / 补充 SERP 证据
```

Dashboard 是主要入口；CLI 是可重复执行和调试入口；Skill 是研究流程入口。

## 3. V1 范围

### 包含

- Steam Top Sellers 和 Popular New Releases 候选；
- Steam 应用详情、genres、categories、评论总数和当前玩家数；
- 基于可见游戏机制的关键词模板和页面级聚类；
- 确定性评分、证据完整度和强制降级；
- 可选 Google Trends 单游戏方向信号；
- 本地 JSON 快照和 Markdown 报告；
- Dashboard 扫描、筛选、排行、详情、状态和错误展示；
- CLI、Codex Skill、离线测试和可选真实接口测试。

### 不包含

- Twitch；
- 数据库、用户系统和云部署；
- DataForSEO、Reddit API 或其他付费 API；
- 自动抓取 Google SERP；
- 自动生成或发布网站；
- 浏览器反检测、Google 自动登录、代理轮换；
- 搜索量、收入或流量预测。

## 4. 默认市场与请求预算

- 市场：`US`；
- Steam 语言：`english`；
- 默认深度分析：10 个游戏；
- 最大深度分析：30 个游戏；
- 同时请求：最多 4 个；
- 单请求超时：15 秒；
- Trends：默认关闭，启用时最多检查 5 个游戏。

市场、语言、采集时间和来源状态必须写入快照与报告。

## 5. 数据契约

### GameCandidate

核心字段：

- Steam app id、名称、图片和来源 URL；
- 发现来源及排行；
- 发布时间、当前玩家、评论总数；
- genres、categories、短描述；
- 推断 mechanics 和 `understanding_confidence`；
- Trends 信号或 `insufficient_data`；
- 结构化 evidence 与 collected_at。

### KeywordCandidate

核心字段：

- 主关键词和支持词；
- 页面类型、搜索意图、触发规则；
- 玩法匹配理由；
- 构建难度和维护等级；
- 评分明细、证据等级和风险。

### ScanSnapshot

核心字段：

- schema version、run id、运行时间、市场、数据状态；
- source statuses；
- games、opportunities、errors；
- `is_demo`，确保示例数据不会被误认为真实扫描。

## 6. 评分模型

### 游戏信号分，0-100

| 维度 | 上限 | 转换规则 |
|---|---:|---|
| Steam 排名 | 30 | 排名按本次候选集线性递减 |
| 当前玩家 | 25 | `log10(players + 1)`，100 万封顶 |
| 评论规模 | 20 | `log10(reviews + 1)`，100 万封顶 |
| 发布时间 | 15 | 30/90/365 天内分别 15/12/8，否则 3 |
| 玩法理解 | 10 | high/medium/low 分别 10/6/2 |

缺失字段贡献 0，但必须降低 `data_completeness`，不能伪造替代值。

### 关键词机会分，0-100

| 维度 | 上限 |
|---|---:|
| 玩家问题强度 | 25 |
| 工具/页面意图 | 20 |
| 开发可行性 | 20 |
| 低维护性 | 10 |
| 游戏信号贡献 | 15 |
| 证据置信度 | 10 |

强制规则：

- 没有 SERP 证据时总分最高 69，状态只能是 `needs_validation`；
- V1 先计算 0-100 规则原始分，再乘以 `0.69` 得到待验证分，以保留相对排序并为需求/SERP 验证预留 31 分；
- 游戏理解为 low 时总分最高 59；
- Trends 缺失不按零需求处理；
- Dashboard 必须把缺失证据显示在分数旁边。

## 9. 实施里程碑

### M1：骨架与数据契约

- Python 包、配置、Pydantic 模型、CLI；
- JSON 存储和报告目录；
- 离线 fixture 测试。

验收：`game-radar --help` 可运行，模型拒绝越界分数和非法 limit。

### M2：Steam 数据闭环

- 两类候选列表、详情、玩家数；
- 超时/空字段/HTML 变化降级；
- raw 与 processed 快照。

验收：真实扫描成功时返回候选；失败时仍生成带错误说明的快照。

### M3：分析和报告

- 玩法推断、模板筛选、聚类；
- 游戏分与关键词分；
- Markdown 报告和放弃/待验证原因。

验收：同一 fixture 多次运行结果一致；无 SERP 时不出现“立即开发”。

### M4：Dashboard

- 总览、雷达、筛选、排行、详情；
- 扫描按钮和后台状态；
- 空、错、部分成功、示例数据状态；
- 响应式和可访问性。

验收：浏览器中可以完成“启动 -> 扫描/示例 -> 筛选 -> 查看证据 -> 下载报告”。

### M5：可选 Trends 与 Skill

- HTTP 模式 Trends provider；
- 最多 5 个游戏、缓存与失败降级；
- Skill 与 reference 文件；
- 安装脚本。

验收：未安装 Trends extra 时主流程正常；Skill 能读取最新快照并输出待验证清单。

## 10. 测试计划

- 模型边界和 JSON 往返；
- Steam HTML 解析、空结果和字段缺失；
- 玩法推断与类型限定关键词；
- 聚类保留原始支持词；
- 评分上限、low confidence 降级、missing Trends 行为；
- 原子写入和 latest 快照；
- 报告包含事实、推断、缺失数据和来源状态；
- API 空状态、示例数据、扫描参数校验和后台冲突；
- 默认测试不访问网络；真实接口测试显式执行。

## 11. V1 完成标准

- 新环境在 5 分钟内完成安装并看到示例 Dashboard；
- 本地服务只绑定 `127.0.0.1`；
- 无数据库、无登录、无 Twitch；
- Steam/Trends 任一失败不会导致页面白屏；
- 所有机会分可追溯到输入字段；
- 页面不把 fixture、推断或缺失数据显示成已验证事实；
- 自动测试通过；
- 至少完成一次真实 Steam 扫描和一次浏览器流程检查。
